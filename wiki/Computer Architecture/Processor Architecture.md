# Processor Architecture（处理器体系结构）

一句话核心：**ISA 在处理器「指令与编码」和「如何实现」之间提供一层抽象；实现上的核心思想是流水线——把一条指令的执行拆成多个阶段并行处理，用暂停（stalling）和转发（forwarding）解决冒险**。

## ISA：指令集体系结构

- **ISA（Instruction-set Architecture）** 定义处理器支持的指令、指令字节编码，以及每条指令会读取/修改的**程序员可见状态**（PC、寄存器、条件码、内存）。
- 指令编码：首字节高四位是 code（操作类型），低四位是 function（细分操作），例如 Y86 的 `rrmovq`、`irmovq`、`jXX`、`call/ret`。
- **CISC vs RISC**：复杂指令集（指令多、编码变长）与精简指令集（指令少、编码规整）两条路线。

## 数字电路与 HCL

- 硬件由三部分组成：**组合逻辑**（计算位的布尔函数）、**存储元素**（寄存器/存储器保存位）、**时钟信号**（控制存储元素何时更新）。
- 逻辑门是最基本的计算元素；组合电路有两条限制：多个门输出**不能相连**、网络必须**无环**。
- 时序电路的关键：**时钟寄存器**存单个位/字，**随机访问存储器**存多个字；两者都由时钟控制更新。

## 顺序实现 SEQ

把任意指令的执行统一拆成六个阶段（顺序执行，一条走完再下一条）：

1. **取指 fetch**：按 PC 从内存读指令；
2. **解码 decode**：从寄存器读最多两个操作数；
3. **执行 execute**：ALU 做算术/逻辑运算，或计算访存有效地址；
4. **访存 memory**：读写内存；
5. **写回 write back**：最多写两个结果回寄存器；
6. **更新 PC**：指向下一条指令。

## 流水线原理

- 把任务拆成多个**相互独立的阶段**，让不同指令的不同阶段在时间上重叠，从而**提高吞吐量**（不是降低单条指令延迟）。
- 局限性：阶段划分不一致、流水线过深会因寄存器延迟而收益下降。
- 带反馈的流水线会产生三类相关：**数据相关、顺序相关、控制相关**，它们是冒险的根源。

## 冒险与解决

- **冒险（hazard）**：数据相关或控制相关导致流水线计算出错。
- **暂停（stalling）**：暂停一条或多条指令，直到冒险不再存在。
- **转发（forwarding）**：把前级算好的结果直接旁路给后级，无需等写回寄存器，多数数据冒险可由此消除。
- 控制相关靠**预测下一个 PC**（分支预测）来缓解。

## 设计经验

- **管理复杂性**是处理器设计的首要问题；硬件设计者必须极度谨慎——芯片一旦流片，几乎不可能改正错误。
