# System I-O（系统级 I/O）

一句话核心：**Unix 把一切 I/O 设备统一模型化为「文件」，所有输入输出都是对文件的读和写；内核用三层共享数据结构表示打开的文件**。

## Unix I/O 模型

所有 I/O 设备（磁盘、终端、网络……）都模型化为文件，所有输入输出统一为四个操作：**打开文件 → 改变文件位置 → 读写文件 → 关闭文件**。

- `open`：把文件名转换为**文件描述符**（返回进程中当前未打开的最小描述符）。
- `read` / `write`：从当前文件位置拷贝最多 n 个字节。
- `lseek`：显式修改当前文件位置。
- 读写会出现**不足值**（返回字节数少于请求），应用程序必须正确处理。

## 内核表示打开文件的三层结构

| 结构 | 作用 | 共享性 |
| --- | --- | --- |
| **描述符表** | 每进程独立，表项由文件描述符索引 | 进程私有 |
| **文件表** | 记录当前文件位置、引用计数、指向 v-node 的指针 | 所有进程共享 |
| **v-node 表** | 包含 stat 结构的大部分信息 | 所有进程共享 |

多个描述符可经不同文件表项引用同一文件；**子进程继承父进程的打开文件**（共享文件表项，故共享文件位置）。

## I/O 重定向

`dup2` 把一个描述符复制到另一个描述符，从而把标准输入/输出重定向到文件——这是 shell 实现 `>`、`<`、管道的基础。

## 该用哪些 I/O 函数

- **Unix I/O**（`open/read/write`）：最底层，最灵活，但不足值需自己处理。
- **RIO 包**：包装 Unix I/O，反复读写直到传完所有请求数据，自动处理不足值——应用不应直接裸调 Unix I/O。
- **标准 I/O 库**（`fopen/fread` 等）：基于 Unix I/O 的高级缓冲例程，对大多数应用更简单。
- 例外：**网络应用更适用 Unix I/O**，因为标准 I/O 与网络文件有相互不兼容的限制（如全双工、有界缓冲等）。
