# Network Programming（网络编程）

一句话核心：**所有网络应用都基于同一个「客户端-服务器」模型，通过「套接字」这一连接端点通信；TCP/IP 协议族抹平了不同网络技术的差异**。

## 客户端-服务器模型

- 每个网络应用由一个**服务器进程**（管理某种资源）和一个或多个**客户端进程**（使用资源）组成；基本操作是**事务（transaction）**。
- 关键认知：**客户端和服务器是「进程」，不是机器或主机**。

## 网络

- 对一台主机而言，网络只是又一种 I/O 设备。
- 层次结构：**LAN（局域网，如以太网）** → **桥接以太网（网桥连接）** → **internet（路由器连接不同 LAN/WAN）**。
- 以太网适配器有全球唯一 48 位地址，数据以**帧（frame）** 传输（含源/目的地址头 + 有效载荷）。

## 全球 IP 因特网

协议软件需两种能力：**命名机制 + 传送机制**，由 **TCP/IP** 协议族实现。从程序员视角，因特网是满足三点的主机集合：

1. 主机映射为一组 **32 位 IP 地址**（点分十进制表示）；
2. IP 地址映射为**域名**（层次结构，由分布式数据库 **DNS** 维护）；
3. 主机上的进程通过**连接（connection）** 通信。

### 连接与套接字

- 连接是**点对点、全双工、可靠**的字节流。
- **套接字（socket）= 连接的一个端点**，由「IP 地址 : 端口」组成。
  - 客户端端口由内核自动分配（**临时端口**）；
  - 服务器端口通常是**知名端口**（Web 80、邮件 25，见 `/etc/services`）。
- 一个连接由两端套接字地址唯一确定，这对地址叫**套接字对（socket pair）**。

## 套接字接口

一组与 Unix I/O 函数结合、用于创建网络应用的函数：`socket`（创建端点）→ `bind/listen/accept`（服务器）与 `connect`（客户端）→ `read/write` 收发字节流。

## Web 服务器与 HTTP

- **HTTP**：基于文本的应用级协议；客户端开连接→请求内容→服务器响应→关闭连接。
- 内容是与 **MIME 类型**相关的字节序列，分两类：
  - **静态内容**：直接取磁盘文件返回；
  - **动态内容**：运行可执行文件并返回其输出。
- **URL**：内容与服务器管理的某个文件的唯一名；后缀 `/` 展开为默认主页（如 index.html）。
- **CGI 标准**：规定客户端如何把参数传给服务器、服务器如何把参数传给子进程、子进程如何把输出发回客户端。
