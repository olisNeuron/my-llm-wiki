# 学习方法与编程实践

这一页收录收藏中关于"怎么学、怎么练、用什么工具"的共识与分歧。总体倾向：**主动产出比被动输入有效，问题驱动比刷量有效，基础决定对 AI 输出质量的判断力**。

## 学习方法

- **QA 法（最朴实的方法）**：拿几张 A4 纸读教材，遇到不懂处写下完整问题（Q1、Q2…），先不回头继续读——用提问把模糊的感觉固化成可查的疑问。
- **学霸为什么刷得快**：先选对书/体系（如数分教材差异、普林斯顿/Thomas 微积分适合自学），再谈速度和题量；框架对了，快才有意义。
- **一到两年成为某领域专家**：用 LLM 深度研究把领域地图摸清（教材、课程、祖师、立学科论文），再逐个板块攻克。
- **刷知乎的代价**：碎片化输入制造"每天都在涨知识"的错觉，但缺少系统连接，对能力提升有限。
- **编程为什么自学难**：资源混杂 + 初学者没有思维框架，容易把数据结构、语言、框架、系统等概念类别搞混。

## 基础与 AI 时代的判断力

- **数据结构/算法在 AI 时代仍必要**：AI 能更快写出代码，但判断它对错、评估复杂度、定位问题仍需要基础；基础的价值是"判断力"而不是"手写红黑树"。
- **为什么感受不到基础学科的作用**：现代软件层层封装把底层隔离了；不是没用，是看不见。
- **为什么啃不下黑皮书**：CSAPP 太重（一学期起步），但"必须从头啃完"可能是个误解——按需、配实验、配合工程问题去读更现实；AI 代码生成工具反而让读系统书变得更必要（需要理解它在改什么）。
- **学完 C 语言什么都干不了**：离硬件太远；花 100 元买 Arduino 套件做小项目，立即获得反馈（温湿度计等）。

## 编程实践与项目

- **怎么找项目**：优先"官方带队的开源训练营"和课程 lab，而不是大海捞针逛 GitHub；项目价值在于过程和复盘，不在数量。
- **避免成为"低级码农"**：从大一就训练自己当便宜劳动力（培训班八股、秒杀/商城系统简历）是自我降级；要积累的是基础、工程能力和可迁移判断力。
- **Debug 能力**：厉害的工程师先问"问题出在哪一层？排除了哪些可能？怎么排除的？"，而不是直接看代码。
- **校招"熟悉 Linux"分层**：入门=会文件操作看日志；合格=常用命令+脚本+排障；优秀=性能调优+快速定位。
- **团队与社区**：有人记录一群人啃 Linux kernel 的长期主义（"笑傲内核"）；小团体式封闭社交则是反面教材（见 [[成长心态]]）。

## 工具与环境

- **Git**：入门用 CS61B 的 6 个视频教程；遇坑用 ohshitgit；以问题为导向学习。
- **编辑器**：Mac 上装 MacVim 的步骤；Vim 是长期投资。
- **远程开发**：Tailscale 组网实现任意网络下 SSH 访问 Ubuntu 工作机 + VSCode Remote，零成本。
- **文件共享**：Linux 配置 samba 的详细步骤（IP、共享目录、权限）。
- **社区工具**：Reddit 入门指南（投票机制、影响力、信息流逻辑）。
- **Pythonic**：符合 Python 哲学（简洁、可读、优雅）的写法，本质是对语言设计思想的遵循。
